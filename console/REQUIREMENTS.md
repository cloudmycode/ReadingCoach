# ReadingCoach Web 文章录入 — 需求说明书

> 状态：已确认  
> 日期：2026-07-27（2026-07-27 收窄范围）  
> 范围：在网页端快速粘贴英文正文并生成文章；精读、复习、统计仍在 iOS App 完成

---

## 1. 背景与目标

### 1.1 背景

孩子在 iOS App 里可以拍照或粘贴录入文章，但以下场景用电脑更方便：

- 家长从试卷 Word/PDF 复制英文段落
- 课外阅读材料在电脑上整理好后一次性粘贴
- 大屏校对、分段粘贴长文

### 1.2 产品定位

**Web 文章录入工具**：孩子账号的网页端录入入口，不是独立的「家长管理系统」。

- 主场景：登录 → 录入文章 → 查看列表 → 查看文章内容
- 非目标：不做学习看板、不做家长绑定、不做网页精读/复习（点词、朗读等）

### 1.3 目标用户

| 角色 | 描述 |
|------|------|
| 实际操作人 | 通常是家长，在电脑浏览器操作 |
| 数据归属 | 登录所用手机号对应的孩子账号（现有 `users` 表） |

### 1.4 成功标准（MVP）

1. 使用孩子学习手机号 + 验证码登录网页  
2. 粘贴英文正文，提交后由服务端拆句翻译并入库  
3. 网页可查看文章列表（标题、句数、时间等）  
4. 网页可查看文章详情（逐句英文 + 中文翻译）  
5. 支持改标题、删文章、单句纠错并重译  
6. 录入成功后，孩子在 iOS App 中也能看到同一篇文章

## 2. 与现有系统的关系

```text
┌─────────────────┐         ┌──────────────────┐
│  iOS App        │         │  Web 文章录入     │
│  （精读/复习）   │         │  （本目录）       │
└────────┬────────┘         └────────┬─────────┘
         │  JWT / 当前 user_id        │ 同一套登录与 API
         └────────────┬──────────────┘
                      ▼
              ┌───────────────┐
              │  Go API + MySQL│
              │  文章拆句入库   │
              └───────────────┘
```

**MVP 直接复用（无需改后端）**

| 能力 | 接口 |
|------|------|
| 发送验证码 | `POST /api/auth/code` |
| 登录 | `POST /api/auth/login` |
| 粘贴正文生成文章 | `POST /api/articles/process-text` |
| 文章列表 | `GET /api/articles` |
| 文章详情 | `GET /api/articles/:id` |
| 修改标题 | `POST /api/articles/:id/title` |
| 删除文章 | `DELETE /api/articles/:id` |
| 修改句子并重译 | `POST /api/articles/:id/sentences/:sentence_id` |

**本阶段不需要**

- 家长账号、家庭绑定、跨用户授权
- 学习看板、生词本、复习进度
- 网页图片 OCR 录入（`POST /api/articles/ocr`）
- 新增服务端接口或数据表

**远期（另立需求）**

- 独立家长账号 + 多孩绑定、学习看板

## 3. 账号模型

### 3.1 MVP 方案（已确认）

| 概念 | 说明 |
|------|------|
| 登录账号 | 孩子的学习手机号（与 iOS App 相同） |
| 权限 | 与 App 登录该账号等价：可读写的都是该 `user_id` 下数据 |
| 安全边界 | 谁能收到验证码，谁就能操作该账号（与 App 一致） |

不做「Web = 家长 / iOS = 学生」的平台角色区分，也不在 JWT 中区分 client 类型。

### 3.2 产品文案建议

- 登录页说明：**请使用孩子的学习账号登录**
- 避免称呼为「家长控制台」，减少账号模型误解

## 4. 功能范围

### 4.1 P0 — MVP（必做）

| 编号 | 功能 | 说明 |
|------|------|------|
| L1 | 登录 | 手机号 + 验证码；Token 存 localStorage 或 Cookie |
| A1 | 文本录入文章 | 大文本框粘贴英文 → 提交 → 等待拆句入库 |
| A2 | 录入结果反馈 | 成功展示文章标题/句数；可跳转详情或列表；失败保留草稿可重试 |
| A3 | 文章列表 | 标题、句数、创建时间、阅读次数；点击进入详情；支持删除（二次确认） |
| A4 | 文章详情 | 标题 + 逐句英文与中译；支持查看与校对 |
| A6 | 改标题 / 删文章 | 详情页或列表操作；删文需二次确认 |
| A7 | 句子纠错 | 单句修改英文并重译（复用现 API） |

### 4.2 明确不做（本阶段）

1. 网页图片 OCR 录入  
2. 家长独立账号与绑定孩子  
3. 学习看板、生词本、复习情况  
4. 网页精读（点词、朗读、提问）  
5. 班级/教师管理

## 5. 功能详述（P0）

### 5.1 登录（L1）

**流程**

1. 输入手机号 → 获取验证码  
2. 输入验证码 → 登录成功 → 进入录入页  

**规则**

- 与 iOS 共用 `POST /api/auth/code`、`POST /api/auth/login`  
- 后续请求携带 `Authorization: Bearer <token>`  

### 5.2 文本录入（A1 / A2）

**主路径**

1. 粘贴英文正文（必填）  
2. 前端校验：非空、合理长度（与现网 `process-text` 一致）  
3. 提交 `POST /api/articles/process-text`，body：`{ "text": "..." }`  
4. 展示 loading（拆句翻译可能需 30～90 秒）  
5. 成功：提示标题与句数，可跳转文章详情、文章列表或继续录入  

**失败与重试**

- 接口报错：保留正文草稿，允许修改后重试  
- 超时：提示「处理较慢，请稍后在文章列表刷新」  

**说明**

- 标题由 AI 自动生成；可在详情页手动修改（A6）  
- 所有 AI / Prompt / 入库逻辑在 `server`，Web 只调 API  

### 5.3 文章列表（A3）

**数据来源**：`GET /api/articles`（支持 `limit` / `offset` 分页）

**展示字段**

- 标题、句数、创建时间  
- 阅读次数、最近阅读时间（有则展示）

**交互**

- 列表按创建时间倒序（与接口默认一致）  
- 点击条目进入文章详情  
- 支持下拉刷新或手动刷新  

### 5.4 文章详情（A4）

**数据来源**：`GET /api/articles/:id`（`:id` 为列表项或录入接口返回的加密 `resource_id`）

**展示内容**

- 文章标题、句数  
- 句子列表：序号、英文原文、中文翻译  

**交互**

- 查看逐句英文与中译，用于确认录入质量  
- 支持改标题、删文章、单句纠错（见 5.5）  
- 提供返回列表入口  
- 注意：调用详情接口会更新阅读统计（与 App 行为一致）  

### 5.5 文章维护（A6 / A7）

**改标题（A6）**

- 接口：`POST /api/articles/:id/title`，body：`{ "title": "新标题" }`  
- 入口：文章详情页  

**删文章（A6）**

- 接口：`DELETE /api/articles/:id`  
- 入口：文章列表或详情页  
- 需二次确认，成功后返回列表  

**句子纠错（A7）**

- 接口：`POST /api/articles/:id/sentences/:sentence_id`，body：`{ "original": "修改后的英文" }`  
- 服务端自动重译该句并更新详情  
- 入口：文章详情页，逐句编辑

## 6. 信息架构（MVP）

```text
登录
 └─ 主框架
     ├─ 录入文章
     │    ├─ 粘贴正文 + 提交
     │    └─ 成功 → 查看详情 / 查看列表 / 继续录入
     ├─ 文章列表
     │    ├─ 点击条目 → 文章详情
     │    └─ 删除文章（二次确认）
     └─ 退出登录

文章详情
 ├─ 查看逐句英文与中译
 ├─ 改标题
 └─ 单句纠错并重译
```

## 7. 部署与域名

与 Go 服务共用同一域名，按路径分流：

```text
https://readingcoach.jingjiangke.com/
├── /          → Web 静态资源（console 构建产物）
└── /api/*     → Go 服务（现有）
```

前端 API 请求使用相对路径（如 `/api/articles/process-text`），无需额外 CORS 配置。

## 8. 非功能需求

| 类别 | 要求 |
|------|------|
| 设备 | 桌面浏览器优先；平板可用 |
| 性能 | 列表首屏 < 2s；拆句提交需明确等待态，禁止无反馈重复点击 |
| 安全 | HTTPS；JWT；不向前端暴露大模型 API Key |
| 兼容 | 现代 Chrome / Safari / Edge 近两个大版本 |
