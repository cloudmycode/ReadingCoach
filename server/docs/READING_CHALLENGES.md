# 阅读小测与家庭奖励服务端

2026-09-22：服务端已部署，iOS 已接入现有千问小测及奖励接口，复用原登录和网络层。已有方案中的家长配置、人工申诉和补差券属于后续扩展，不是本次已实现能力。

## 运行与配置

使用现有 Go 服务、MySQL **8.0+**（任务领取使用 `SKIP LOCKED`），不新增 Redis、消息队列或支付服务。服务启动执行嵌入的幂等建表迁移 `db/migrations/20260920_add_reading_challenges.sql`。正式环境也可先由迁移账号执行此 SQL；应用启动校验建表失败时终止启动，避免无持久化任务的半可用状态。

小测与文章拆句、翻译共用现有 `AIService` 实例和以下千问配置，无需新增小测 Key 或独立客户端：

```json
{
  "QwenAPIKey": "现有 DashScope Key",
  "QwenAPIURL": "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
  "QwenModel": "qwen-plus"
}
```

已有千问配置可直接复用。密钥仍只保存在服务端，沿用文本和视觉 Key 互为缺省的逻辑。小测生成、质量检查、批改和自动复核均调用原有 `CompleteJSONPrompt`，使用 JSON 对象输出；不发送 DeepSeek 专用参数。

原先新增的 `QuizAI` 配置与 `QUIZ_AI_*` 环境变量已移除，旧配置文件残留这些字段会被忽略，可以删除。后台仍使用两个工作者，不额外增加一套 AI 配置。

未配置千问 Key 时，待处理小测保留为 `queued`；补齐现有 `QwenAPIKey` 配置并重启后继续。当前测试使用受控 AI 响应，正式使用前仍需用实际年级文章和答案验证模型判分质量。

```sh
cd server
go test ./...
go vet ./...
go run ./cmd/server
```

## 已实现的规则

- 上传文章及修改原文时，在文章写入的**同一数据库事务**建立不可变文章快照和出题任务；历史文章首次请求小测时补建。
- 精确原文及句子 ID 决定小测版本。修改原文后，旧听读进度不能解锁新版小测，旧版提交被拒绝。已提交的答案仍按提交时的原文和评分标准完成批改。
- 五道开放题，至少三种形式：原句翻译、文中词义、句意、理解、总结。生成标准答案、必需要点、可接受表述和错误边界；程序验证数量、引用、类型和题号，并通过第二次 AI 调用检查题目质量。引用逐字存在且能唯一定位时，自动纠正模型填错的句子 ID，再送独立审核；不模糊匹配、不改写引用，无原文依据或位置不明仍拒绝。质量不合格进入后台重试。
- 公开题目接口只有题干和原文引用，没有标准答案、评分要点或生成原始响应。提交后查询自己的逐题判定与反馈。
- 客户端在每句英文音频**自然播放完成**时上报一次，绑定 `paper_id + content_hash + sentence_id`。支持分次听读；服务端检查全部句子，不接受“最后一句已播完”代替全文。该机制验证记录完整性，不能证明孩子实际听懂或阻止修改版客户端伪造播放事件。
- 五题同次提交，各题 0/20 分，由服务端求和，80 分通过。空答案不计分；语义正确的同义表达应接受，不因不影响理解的语法或拼写小错扣分。
- AI 不能确定时自动独立复核一次，仍不确定返回 `review_required`、`score: null`，不显示零分、不计达标。可重新提交答案；本版未提供家长人工裁决或已评分申诉。
- 每账号每日最多 30 次新的提交；同一试卷同时只允许一份待处理提交。成功批改不可通过重试接口重新抽取评分。
- 首次进入挑战或首次有效提交时，按 `Asia/Shanghai` 自然日开始 30 天周期。规则及时间区间写入周期快照；跨月仍按 30 天，不是自然月；中断不清零。未访问、未学习的整段周期不创建空记录。
- 每个自然日最多一条达标记录。一个已通过的文章及其原始文章链只奖励一次；大小写、空白变化、删后重导相同内容不能重复获得天数。不同实质内容不是语义查重。
- 日期以**服务端接受提交的时间**为准，客户端不能回填日期。批改跨午夜仍归入提交日。离线期间未上传的完成不能补签。
- 5/14/21/26/28/29/30 天对应 1–7 星、5/10/15/20/25/35/50 元；金额存整数分。周期结束仅发最高档一张券，不累加。30 天全部达标且没有待批改时可立即结算。
- 过期周期有待批改时暂缓发券；AI 系统故障耗尽重试后仍保留待处理提交，修复服务并重试后结算。`review_required` 是已完成自动复核的无分数结果，不阻塞周期，新提交可重新争取当日达标。
- 每分钟扫查到期周期，批改结束也触发结算，不要求用户打开 App。兑换券只用于给家长展示；点击兑换后记录服务器时间，重复请求返回同一记录，不调用银行或支付接口。

## HTTP 接口

未就绪的小测包含 `preparation: {"attempts": 1, "max_attempts": 5, "started_at": 1789990000}`：尝试次数、尝试上限、试卷建立时间（Unix 秒），就绪时省略。客户端仍以 `status` 和 `unlocked` 判断是否可答题，不用计时猜测完成；旧客户端可忽略新增字段。服务端日志只记录失败阶段与超时分类，不记录模型响应或凭据。

统一前缀 `/api`，全部使用现有 JWT 和用户归属校验。返回沿用 `{ "success": true, "message": "ok", "data": ... }`。文章 `:id` 使用原有加密 ID；小测、提交、周期和兑换券 ID 是整数，不能依靠 ID 隐藏代替权限检查。

| 方法 | 路径 | 结果 |
|---|---|---|
| GET | `/articles/:id/quiz` | 当前版本、状态、公开题目、已听句子、`unlocked`；未就绪时附 `preparation` |
| POST | `/articles/:id/listening-completions` | 幂等记录一句自然播放完成 |
| POST | `/articles/:id/quiz/attempts` | HTTP 202，返回提交记录和批改状态 |
| GET | `/articles/:id/quiz/attempts` | 本篇最近 50 次提交 |
| GET | `/reading/attempts/:attempt_id` | 轮询状态、五题反馈、总分、是否通过 |
| POST | `/reading/attempts/:attempt_id/retry` | 仅重试已耗尽自动重试的系统失败 |
| POST | `/reading/papers/:paper_id/retry` | 仅重试失败的出题任务 |
| GET | `/reading/challenge` | 当前周期、日期、达标日期数组、最高星级、七档规则 |
| GET | `/reading/cycles` | 最近 24 个已有周期，含等待结算状态 |
| GET | `/reading/vouchers?status=available&limit=50&offset=0` | 券列表；状态可为 available/redeemed，省略查全部 |
| POST | `/reading/vouchers/:voucher_id/redeem` | 原券记录，`status: redeemed` 和首次兑换时间 |

听读请求：

```json
{"paper_id":12,"content_hash":"GET quiz 返回的版本指纹","sentence_id":103}
```

提交请求（五个题号各一次；请求体最多 64 KiB，每题最多 2000 字符）：

```json
{
  "paper_id": 12,
  "request_id": "客户端为本次提交生成的UUID",
  "answers": [
    {"question_id":1,"answer":"答案一"},
    {"question_id":2,"answer":"答案二"},
    {"question_id":3,"answer":"答案三"},
    {"question_id":4,"answer":"答案四"},
    {"question_id":5,"answer":"答案五"}
  ]
}
```

`request_id` 是 8–80 位字母、数字、下划线或连字符。网络重发必须复用同一个 ID 和答案；相同 ID 换内容返回 409。新一轮答题使用新 ID。

状态：题目 `queued → running → ready`，失败最终 `failed`；提交 `queued → running → graded / review_required`，系统失败最终 `failed`。自动重试期间重新为 `queued`。`score` 在评分未明确前为 null；`passed` 不等于新增达标日，重复文章可答题通过但不重复奖励，客户端以挑战接口为准。

日期字符串为 YYYY-MM-DD，时间戳为 Unix 秒；当前周期的 `today` 按冻结的时区计算。

错误：400 参数错误，401 未登录，404 不存在或非本人资源，409 版本冲突、未听完、已有处理中提交、频率限制或当前不允许重试，500 系统异常。不给客户端返回数据库或 AI 原始错误。

## 已实现的客户端接入

1. 阅读页获取 `quiz`，保存当前版本；若原文变动，重新拉取。
2. 复用现有自然播放完成回调，逐句上报；上报失败保留本地队列，在同版本内重试。
3. 全文已听且 `status=ready` 才启用开始小测；区分排队、出题审核、自动重试（显示尝试次数）、失败。超过 90 秒提示稍后回来，提供刷新题目，已听记录保持不变；只有失败任务允许手动重试。
4. 五题同页、底部唯一提交；保留本地草稿。发起请求后保存 `attempt_id`，短时轮询，离开页面不取消服务端批改；重新进入可通过本篇记录恢复。
5. 通过后刷新挑战与券列表。用 `completed_dates` 点亮实际日期，不按列表数量硬填前 N 颗星。
6. 兑换成功只更新当前卡片按钮为“兑换成功”并禁用；不切换已兑换分类。用户主动切换或重新进入后再按状态归类，兑换失败保留未兑换状态。
7. 客户端使用 `ReadingAPI` 复用 `NetworkManager`，`ReadingQuizStore` 管理文章版本、听读队列与提交恢复，`ReadingChallengeStore` 管理服务端周期和分页券列表。正式入口不保留模拟题目或模拟评分。
8. 客户端回归验证：在仓库根目录运行 `iosclient/ReadingApp/PreviewTests/run.sh`。包括真实 HTTP 封装的 JWT、202/401/409，听读断网恢复、跨语言版本哈希、请求重发、账号隔离、未确定评分与兑换交互；受控响应不代替真实模型的评分质量验收。

## 复用与可靠性

`ReadingService` 按职责拆成类型/校验、文章小测、后台任务、奖励账本四个文件，复用事务、文章快照、JSON 客户端和现有鉴权，不为每个界面复制一套逻辑。

任务以 MySQL 持久化，短事务领取，AI 调用在事务外执行，最长 240 秒，租约 300 秒。多个实例用 `SKIP LOCKED` 竞争，租约令牌限制过期工作者提交结果。最多五次后台尝试，指数退避；手动重试只恢复同一不可变输入。进程退出会取消调用，残留任务在租约到期后恢复。

账号行锁串行化同一用户的奖励账本写入；唯一索引分别保护请求幂等、每日一次、文章一次、每周期一券。奖励相关事务使用 READ COMMITTED，避免等待账号锁后继续读到旧快照。券兑换采用原子 `COALESCE` 保留首次时间。

数据库保留题目、评分标准、生成与质量检查响应、提交原文、批改原始结果，支持问题追溯。阅读接口的请求与响应正文不进入调试日志；出题/批改失败日志只记录类别。删除文章不删除已提交的快照、达标记录和券，避免奖励历史丢失。

## 验证

单元测试覆盖：开放题结构与引用、标准答案隔离、0–100 分及 80 分门槛、空答/不确定判定、时区/跨月/闰日、内容指纹、千问共享客户端 JSON 请求、旧小测配置不覆盖千问配置、接口鉴权和请求大小限制。

真实 MySQL 集成测试使用独立临时数据库，测试结束删除自己创建的数据库，不接触业务数据库：

```sh
# DSN 数据库名必须以 reading_test 开头；账号需要创建测试数据库权限。
READING_TEST_DSN='root:reading-test-local@tcp(127.0.0.1:13316)/reading_test?parseTime=true' \
  go test -race ./...
```

未设置 `READING_TEST_DSN` 时，集成测试明确标记跳过，普通测试通过不代表数据库集成通过。覆盖并发幂等提交、听读门槛、版本失效、跨日批改、周期最高档结算、重复兑换、任务租约恢复、失败重试、账号隔离及删除重导去重。所有 AI 测试使用可控响应，不能代替真实模型的教学质量评估。
